# خطة نشر مجالس العرب بأقل تكلفة

هذه الخطة لا تفتح الإنتاج ولا تغيّر قاعدة البيانات. الغرض منها ترتيب قرار النشر والتحقق منه قبل أي تغيير قد يؤثر في بيانات المستخدمين.

## الحالة التي يجب أخذها بالحسبان

- التطبيق Next.js مع TypeScript وPrisma وBetter Auth.
- مخطط Prisma الحالي يستخدم SQLite.
- حاجز الإطلاق في `src/middleware.ts` يعيد HTTP 503 لمسارات التطبيق في بيئة الإنتاج عمدًا. لا يُحذف هذا الحاجز لمجرد نجاح البناء.
- Codespaces غير متاح حاليًا بسبب بلوغ حد الاستخدام/الميزانية.
- فحوص GitHub Actions على الالتزام `0c8a2415c36336470972243a9fc022a6bf888f33` لطلب السحب #118 نجحت، لكن هذا لا يثبت تشغيل التطبيق أو اكتمال مراجعة التفويض.

## المسار المقترح

1. **التحقق من النشر المجاني الحالي قبل اختياره:** راجع حدود الاستخدام الحالية، دعم Next.js، تشغيل وظائف الخادم، متغيرات البيئة، وإمكانية نشر تطبيق تجريبي خاص/محدود.
2. **اختيار قاعدة البيانات قبل النشر:** لا تعتمد على ملف SQLite محلي داخل بيئة استضافة مؤقتة. إما اختيار خدمة تدعم تخزينًا دائمًا موثوقًا لملف SQLite مع قيود التشغيل المناسبة، أو تخطيط ترحيل مُختبَر إلى PostgreSQL. لا تغيّر موفر Prisma مباشرة على الإنتاج.
3. **اختبار الترحيل على نسخة منفصلة:** خذ نسخة احتياطية، اختبر تحويل المخطط والبيانات والعلاقات، وقارن عدد السجلات ونتائج اختبارات العزل قبل التفكير في الإنتاج. لا تنفذ أي حذف أو إعادة ضبط لقاعدة البيانات.
4. **تجهيز أسرار الإنتاج:** إعداد HTTPS، `BETTER_AUTH_SECRET` قوي، `BETTER_AUTH_URL`، الأصول الموثوقة، وSMTP. تخزن الأسرار في إعدادات الاستضافة فقط، لا في Git أو متغيرات `NEXT_PUBLIC_*`.
5. **إكمال المراجعة الأمنية:** فحص كل Server Action وAPI route يكتب بيانات، والتحقق من العضوية والصلاحيات على الخادم، وإضافة اختبارات سلبية للعزل بين مساحات العمل والتحقق من البريد، ثم تشغيل الاختبارات على نفس commit المراد نشره.
6. **نشر نسخة معاينة:** اختبار إنشاء حساب وتسجيل الدخول/الخروج وإنشاء مساحة عمل ومنشور وتعليق وتفاعل، والبحث، وقائمة المراجعة، مع التأكد من أن البيانات تبقى بعد إعادة النشر.
7. **فتح الإنتاج فقط بعد الأدلة:** مراجعة النتائج والنسخ الاحتياطي والاستعادة وخطة التراجع وموافقة صاحب المشروع. بعدها فقط يمكن تغيير حاجز 503 في تغيير مستقل ومراجع.

## شروط القبول

- [ ] لا يوجد اعتماد على Codespaces لتشغيل الموقع العام.
- [ ] عنوان HTTPS يعمل ويُعاد فتحه من جهاز آخر.
- [ ] المصادقة والجلسات والبريد مجرّبة.
- [ ] عمليات الكتابة محمية بالعضوية والتفويض.
- [ ] لا يمكن لعضو في مساحة عمل قراءة أو تعديل بيانات مساحة أخرى دون صلاحية.
- [ ] بيانات القبائل والمصادر غير مختلقة؛ المقترحات تبقى غير مراجعة حتى يعتمدها إنسان.
- [ ] قاعدة البيانات دائمة والنسخ الاحتياطي والاستعادة مُختبران.
- [ ] فحوص الاختبارات وESLint وTypeScript والبناء والأمان ناجحة على commit النشر نفسه.
- [ ] إزالة حاجز الإطلاق تمت بعد مراجعة مستقلة، لا لإخفاء حالة 503.

## ملاحظات التكلفة

لا يُفترض أن أي خطة مجانية دائمة أو كافية قبل مراجعة شروطها الحالية. لا تُضف بطاقة دفع أو ترفع ميزانية الاستخدام لهذا المسار دون قرار صريح. تجنب تشغيل خدمات مدفوعة أو ترحيل قاعدة البيانات قبل التأكد من التكاليف والقيود.
