# مجالس العرب — منصة التواصل العربي

منصة عربية RTL للمجالس والحوار بين الأعضاء، مع منشورات وتعليقات وتفاعلات داخل مساحة العمل، ودليل بحثي منفصل للكيانات والمصادر والأدلة. المبدأ: تواصل عملي أولًا، وتوثيق واضح عند استخدام السجل البحثي.

## الحالة الحالية

نسخة MVP قيد التطوير. المسار الرئيسي هو `/council` للمجلس والتواصل، والمسار `/research` للدليل البحثي، والمسار `/assistant` للمساعد المحايد. ليست جاهزة للإطلاق العام حتى الآن.

- Next.js وTypeScript وPrisma مع قاعدة SQLite.
- تسجيل دخول بالبريد وكلمة المرور وخيار Google OAuth عبر Better Auth. يتطلب Google OAuth إعداد GOOGLE_CLIENT_ID وGOOGLE_CLIENT_SECRET وتسجيل عنوان العودة الدقيق في Google Cloud Console.
- إنشاء مساحة عمل وعضويات بأدوار أولية، مع تحقق خادمي من العضوية عند اختيار المساحة.
- كتالوج بحثي **مشترك للقراءة** بين مساحات العمل: الكيانات والعلاقات والمصادر ومقاطع الأدلة والادعاءات والأماكن. يجب أن تكون هذه السجلات عامة وغير سرية.
- يحتوي فهرس البحث على 170 مرشح اسم من ثماني دفعات مرتبطة بمصادر؛ تظهر حالة المراجعة والرابط والموضع عند توفره. هذه المرشحات ليست قبائل مؤكدة ولا تُحوّل تلقائيًا إلى كيانات معتمدة.
- يمكن لأعضاء المجالس المرتبطة بسجل قبيلة موجود إضافة معلومات إلى ملفها المشترك؛ تظهر المساهمات بحالة «غير مراجع» مع المصدر المقدم إن وجد، ولا تُعامل كحقائق تاريخية. أما أسماء القبائل غير المسجلة فتبقى في قائمة المراجعة الخاصة بالمجلس حتى اعتماد السجل.
- تسجيل بيانات المصادر ومقاطع الأدلة متاح لأمين كتالوج معتمد عبر `CATALOGUE_CURATOR_EMAILS`، مع تحقق مدخلات وسجل تدقيق. لا يعني التسجيل أن الكتاب قُرئ أو أن محتواه تم التحقق منه.
- عند ضبط `OPENAI_API_KEY`، تُستخدم خدمة خلفية اختيارية لاقتراح مسودات ادعاءات من نص المقطع فقط. يُشترط تطابق الاقتباس حرفيًا مع المقطع، وتبقى كل مسودة في قائمة مراجعة خاصة بمساحة العمل؛ ولا تُنشر تلقائيًا أو تُعلَن صحيحة. لا يظهر اسم التقنية أو واجهة محادثة في واجهة المستخدم. عند غياب المفتاح تتوقف هذه الخطوة بهدوء. المقاطع المرسلة إلى مزود الخدمة تُعالج خارجيًا؛ لا تضبط المفتاح قبل الموافقة على ذلك.
- صفحة `/assistant` تقدم محادثة عربية لتلخيص النصوص ومقارنة الروايات وتنظيم النقاش وفق ميثاق الحياد في `docs/MAJALIS_AGENT_SPEC.md`. تتطلب `OPENAI_API_KEY` كي ترد؛ ويظل المفتاح على الخادم، وتُرسل الطلبات مع `store: false`، ولا تُحفظ رسائل المحادثة في قاعدة بيانات المنصة. قد يعالج مزود الخدمة النصوص المرسلة خارجيًا؛ لا تُدخل بيانات حساسة، ولا تضبط المفتاح إلا بعد الموافقة على ذلك.\n- ملاحظات مساحة العمل وطلبات الإضافة والقرارات وسجلات التدقيق ومنشورات المجلس مرتبطة بمساحة العمل. اختبارات SQLite للتحقق من العزل واختبارات دورة المصادقة متاحة، كما أُضيفت اختبارات مباشرة لبعض المسارات الحساسة؛ تبقى مراجعة جميع عمليات الكتابة ومراجعة أمنية مستقلة مطلوبة.
- الواجهة لا تعرض بيانات بحثية تجريبية ثابتة بوصفها بيانات حقيقية؛ الأرقام تُقرأ من قاعدة البيانات.

سياسة الرؤية: [الكتالوج المشترك وخصوصية مساحة العمل](docs/CATALOGUE_VISIBILITY_AND_WORKSPACE_PRIVACY.md).

## التشغيل عبر GitHub Codespaces

1. افتح المستودع واختر **Code → Codespaces → Create codespace on main**.
2. تنتظر البيئة حتى تنتهي التهيئة التلقائية: تثبيت الاعتماديات، إنشاء `.env` تطويري خاص إذا لم يكن موجودًا، تطبيق الترحيلات وتوليد Prisma Client، ثم إدخال بيانات المصادر الببليوغرافية ومقطع المصدر العام بأوامر قابلة للتكرار.
3. افتح منفذ التطبيق 3000 بعد بدء الخادم. المنفذ مضبوط ليكون خاصًا، وليس رابطًا عامًا للنشر.
4. ابدأ بإنشاء حساب ثم مساحة عمل. قاعدة البيانات محلية داخل بيئة التطوير ولا تُشارك ملفها أو أسرار `.env`.

## التشغيل المحلي

1. استخدم Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env`.
3. ثبّت الاعتماديات بدقة من ملف القفل: `npm ci`.
4. تحقّق من متغيرات البيئة المطلوبة، ثم طبّق الترحيلات: `npm run db:deploy`.
5. ولّد Prisma Client: `npm run db:generate`.
6. شغّل التطبيق: `npm run dev`.

### استكشاف أخطاء التسجيل محليًا

- إذا ظهر `Invalid origin` في الاستضافة، يجب أن يطابق `BETTER_AUTH_URL` النطاق الأساسي المنشور حرفيًا، وأن يحتوي `BETTER_AUTH_TRUSTED_ORIGINS` على الأصول الإضافية المعتمدة فقط. أُضيف دعم ترويسات النطاق والبروتوكول التي تضبطها reverse proxy الموثوقة. لا تستخدم wildcard، ولا تعتبر الإصلاح مؤكدًا قبل تجربة الموقع المنشور.
- إذا ظهر `Too many requests`، توقف عن تكرار المحاولات؛ حد التسجيل الافتراضي 3 محاولات في الساعة. بعد التأكد من أنك في بيئة تطوير محلية، استخدم `npm run auth:dev-reset-signup-limit` لمسح عدادات التسجيل فقط. يرفض الأمر العمل في الإنتاج ولا يمس المستخدمين أو الجلسات أو عدادات تسجيل الدخول.
- يتطلب أمر الاستعادة وجود `DATABASE_URL` في `.env`. لا تشارك ملف `.env` أو أي أسرار.

في بيئة الإنتاج يلزم إعداد `BETTER_AUTH_SECRET` عشوائي بطول 32 حرفًا على الأقل، و`BETTER_AUTH_URL` بعنوان HTTPS الرسمي المطابق للموقع، وإعدادات SMTP. لتفعيل Google، أنشئ OAuth Client من نوع Web في Google Cloud Console، وأضف `https://YOUR_CANONICAL_DOMAIN/api/auth/callback/google` إلى Authorized redirect URIs ثم خزّن `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` في أسرار الاستضافة. استبدل YOUR_CANONICAL_DOMAIN بالنطاق الحقيقي؛ لا تضع الأسرار في GitHub أو في متغيرات `NEXT_PUBLIC_*`. إذا كانت الاستضافة خلف reverse proxy، يجب أن تضبط المنصة `x-forwarded-host` و`x-forwarded-proto` بنفسها لا أن تمرر قيمًا يرسلها العميل. عيّن `CATALOGUE_CURATOR_EMAILS` إلى قائمة عناوين البريد المعتمدة مفصولة بفواصل فقط بعد تعيين أمناء موثوقين؛ تركه فارغًا يمنع تسجيل المصادر. `OPENAI_API_KEY` اختياري ويُستخدم على الخادم فقط؛ لا تضفه إلى متغيرات `NEXT_PUBLIC_*`. لا تستخدم قيم CI أو بيانات تجريبية في الإنتاج.

## إدخال المصادر والمقاطع الأولية

`prisma/seed-bibliography.mjs` يسجل بيانات فهرسية فقط. و`prisma/seed-public-domain-passage.mjs` يسجل مقطعًا من النص الإلكتروني المفتوح لكتاب «صفة جزيرة العرب» مع رابط الموضع، من دون إنشاء كيان قبلي أو ادعاء تاريخي. كلا الأمرين قابل للتكرار، وحالات المراجعة تبقى غير مؤكدة إلى أن يتحقق باحث بشري من النسخة والموضع.

## التحقق الآلي

تشغّل GitHub Actions التحقق من مخطط Prisma، وتوليد العميل، والاختبارات، وESLint، وبناء الإنتاج، وتدقيق الاعتماديات. توجد اختبارات وحدة أولية للصلاحيات والتحقق من المدخلات وأمان الروابط وبوابة الإطلاق؛ أما اختبارات تكامل قاعدة البيانات وواجهات API والعزل بين المساحات فما زالت مطلوبة.

## ما يمنع الإطلاق

- إعادة التحقق من الاعتماديات والبناء على commit الإطلاق نفسه بعد اكتمال الدمج.
- استكمال جرد التفويض لكل Server Action ومسار يكتب بيانات، وإضافة اختبارات سلبية مباشرة للمسارات التي لا يغطيها الاختبار الحالي.
- تحديد سياسة إلزامية واضحة للتحقق من البريد عند التسجيل؛ الإعداد الحالي لا يشترط التحقق بعد إنشاء الحساب.
- ضبط SMTP الفعلي، والنطاق الرسمي عبر HTTPS، وسر إنتاج عشوائي، والنسخ الاحتياطي والاستعادة، والمراقبة.
- تجربة الترحيلات على نسخة من قاعدة بيانات الإنتاج إن وجدت، وتوثيق التراجع والاستعادة.
- مراجعة حقوق الوصول إلى المصادر وحقوق النصوص، ثم إتمام مراجعة أمنية مستقلة قبل فتح بوابة الإنتاج.

**بوابة الإنتاج مغلقة عمدًا.** يعيد middleware استجابة HTTP 503 لمسارات التطبيق في الإنتاج حتى تُغلق موانع الإطلاق وتُراجع الأدلة. لا تزل هذه البوابة لجعل النشر يبدو متاحًا.
